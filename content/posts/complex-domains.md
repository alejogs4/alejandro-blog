Something I love seeing a demo of a new flashy product or AI agent (people doesn't build anything else nowadays) it's that despite working on tech for a while it is easy to understimate the whole spectrum of moments where a software system can go wrong. That input we didn't expect or the case we didn't have in mind either because it is genuinely rare or we don't know enough of the domain to even have it in consideration because this domain by itself it is complex.

## We build like we know

The speed on pre and post AI era it's as big as how much we know about the domain under construction, the exact domain terms that used right can influence the direction agents take by giving them in few words the right clues of: where the code should be located, which software components should be interacting and under which rules those component execute their mission. All of this needs somewhere, you call it a human brain for the nostalgic or a knowledge graph for the hipsters but we need to encode this knowledge somewhere, not optional since no complex domain can be turned into a working software without this.

Regardless of where you place this knowledge, this knowledge needs curation, cleaning and a technical-product centric interpretation for software construction and on this inherent complexity still exist a bottleneck on the speed and autonomy an AI agent can received. Autonomy can only be granted as long as  whoever has it have the right context to under a proper guardrail system have the exact and precise context provided but to build this context in the first place the problem itself needs research, learning and understanding.
